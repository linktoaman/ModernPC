# Login Page Release Gate Evidence

## Scope

This evidence covers the frontend-only Shopify login page route from `theme/templates/customers/login.json`, `theme/sections/main-login.liquid`, `theme/snippets/login-configuration.liquid`, `theme/config/settings_schema.json`, and `theme/assets/theme.css`.

## Automated Checks

| Gate | Evidence | Result |
|---|---|---|
| Required UI elements | `node tests/login-navigation.test.js` and `node tests/login-page-release-gates.test.js` assert the configured logo area, configured page title, exactly one SSO button, help link, and reserved empty status region. | Pass |
| Empty status behavior | `tests/login-page-release-gates.test.js` asserts the status region is empty and does not render undefined, placeholder, or fabricated error text. | Pass |
| Navigation targets | The tests assert SSO and help links use direct browser navigation to configured theme URLs and that Liquid disables non-HTTPS destinations with `#`. Real authentication is intentionally not exercised. | Pass |
| Sensitive fields | The tests assert no form, input, textarea, select, credential, registration, recovery, payment, financial, health, or sensitive personal data fields exist on the login page. | Pass |
| Accessibility | The tests assert `role="status"`, `aria-live="polite"`, readable red-theme contrast for the SSO button and help link, and visible `:focus-visible` styles for keyboard users. | Pass |
| Visual regression contract | The tests assert the login card element order and required CSS structure for the two-column shell and login card spacing. This is source-level visual coverage for this repository because no browser visual snapshot runner is present. | Pass |
| E2E smoke contract | The tests assert the customer login route renders only the `main-login` section and that the route exposes required elements and configured navigation targets. Hosted Shopify preview smoke testing should repeat this against the launch candidate URL. | Pass |
| Performance | The tests assert no blocking external login-page assets or browser authentication calls are added before initial render, render telemetry is deferred, and source-level contract validation completes under 5 seconds. Hosted standard-broadband timing remains a release-candidate evidence item when the approved environment is available. | Pass |
| Dependency/CVE and SBOM | No repository package manager manifest or lockfile exists for this Shopify theme workspace. High and critical findings still block release when the existing CI/platform scan produces dependency or platform findings, unless handled through the approved exception process. | Not applicable in repo; required at CI/platform gate |

## Commands

Run from the workspace root:

```sh
node tests/login-navigation.test.js
node tests/login-page-release-gates.test.js
```

## Release Hold Rules

- Hold release if either login page test command fails.
- Hold release if Shopify preview smoke testing shows missing required elements, non-HTTPS SSO/help destinations, failed keyboard focus visibility, unreadable contrast, or initial render at or above 5 seconds on the approved standard broadband environment.
- Hold release on any high or critical dependency/CVE finding unless resolved or approved through the existing exception process.
- Hold release if SBOM evidence cannot be generated by the existing CI/platform process once a package or platform dependency inventory is available.
